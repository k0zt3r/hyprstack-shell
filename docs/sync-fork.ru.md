# Обновление личного форка

Из корня репозитория:

```sh
./sync-fork.sh                         # показать настройки, ничего не менять
./sync-fork.sh --apply --push           # сохранить правки, объединить и отправить
```

Здесь `origin/main` — оригинал, `fork` — ваш GitHub, а целевая ветка — текущая
локальная ветка (сейчас `kali-support`). Merge сохраняет исходные коммиты и
авторов. История не переписывается; force push не используется.

Перед объединением создаётся резервная копия в
`~/.local/state/hyprstack/fork-sync/`: исходный HEAD, двоичный diff, новые файлы
и конфигурация Hyprstack/Hyprland. Архивы могут содержать личные данные: они
остаются на компьютере, не добавляйте их в Git.

Все изменения уже отслеживаемых файлов, включая удаления и ранее добавленные
в индекс правки, попадут в отдельный коммит. Новые файлы нужно предварительно
добавить через `git add` либо перечислить явно:

```sh
./sync-fork.sh --apply --push \
  --include sync-fork.sh --include distribution/sync_fork.py \
  --include docs/sync-fork.ru.md
```

Не добавляйте секреты и личные настройки в репозиторий. Настройки из домашней
папки резервируются локально, но не копируются в форк. Ручные правки только в
`~/.local/share/hyprstack` нужно сначала перенести в соответствующие исходники:
скрипт коммитит изменения репозитория, а не произвольные файлы установки.

При конфликте отправка и установка не выполняются. Выполните `git status`,
исправьте конфликтующие файлы, затем `git add <файлы>` и `git merge --continue`.
Повторите команду синхронизации. Отмена незавершённого объединения:
`git merge --abort`; коммит ваших доработок останется в истории.

Синхронизация сама по себе обновляет исходники и форк. Для сборки и установки
выйдите из Hyprland, войдите в TTY и выполните:

```sh
./sync-fork.sh --apply --install --push
```

Используется штатный `./update.sh --no-pull`, с его проверками зависимостей,
резервной копией и ограничениями платформы. На Kali сборка может потребовать
подготовленное окружение из INSTALL.kali.md. Установка запускается до отправки;
при её ошибке отправки не будет. Штатный установщик может обновлять стандартные
конфиги: полная копия прежних настроек остаётся в указанном выше архиве.
Откат установки: `./update.sh --rollback`.

Первый merge может потребовать ручного разрешения конфликтов: локальный фикс
значков файлов пересекается с изменениями оригинала.
